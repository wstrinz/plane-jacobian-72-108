t4_state.pkl — provenance and pickle-trust note
================================================

The verification path NO LONGER unpickles this blob. The pre-resultant
generators G1,G2,G3,G5body (plus the derived H2,H3 and sol4) are shipped as
exact integer/rational term lists in `generators.json` (variable order and a
sha256 of this pickle are recorded there). The mandatory checkers
`f37_sat_verify.py`, `f37_free_family_verify.py`, and the Lean exporter
`lean_export/export_certificate.py` all parse `generators.json` — nothing on the
mandatory path calls `pickle.loads()`.

`t4_state.pkl` is kept only for OPTIONAL provenance: when it is present, the
checkers (via `system_generators.verify_pickle_provenance`) re-load it and
confirm `generators.json` reproduces it exactly (and matches the recorded
sha256). This step is skipped gracefully if the pickle is absent.

Pickle-trust: unpickling can in principle execute arbitrary code, which is
exactly why it was removed from the mandatory path. If you would rather not trust
the shipped blob at all, delete it (the suite still passes from `generators.json`
alone) or rebuild everything from scratch with

    python3 regenerate_system.py

which regenerates the state object (needs the exact-arithmetic deps in
requirements.txt / requirements-lock.txt); `generators.json` was emitted from it
once and round-trips against it exactly.
